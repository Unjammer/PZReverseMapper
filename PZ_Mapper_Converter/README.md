# PZ Reverse Mapper Converter

Small command-line converter for compiled Project Zomboid map cells.

Published CLI binary: `PZReverseMapper.Cli.exe`.

It reads `.lotheader` and `world_X_Y.lotpack` files, supports old `300x300`
cells and new POT/v42 `256x256` cells, then writes WorldEd-style `300x300`
TMX cells plus a `.pzw` project file.

If an `objects.lua` file is present in the input folder, objects are parsed and
written back into the `.pzw` cells on the target `300x300` grid. Rectangle
objects, polygons, polylines, line width, and arbitrary object properties are
preserved.

PNG preview images are generated by default. Per-cell `base`, `full`, and
`vegetation` images are written under `maps_img/`, then merged into `Map.png`,
`Map_veg.png`, and `world.png`. `Map.png` is the base terrain image used by the
world workflow and does not draw RoomDefs visually. When zombie density data is
available, the converter also writes `Map_ZombieSpawnMap.png`.

For unfiltered Build 42 exports, if the input folder contains
`maps/biomemap_X_Y.png` tiles, the converter assembles them into a complete
`biomemap.png`. Filtered `--cells` test exports skip this global biomemap to
keep small validation runs lightweight.

Use `--extract-tiles` to extract Project Zomboid `.pack` assets from the
`--tiles` path. Raw atlas images are written to
`TilesRaw/<physical-pack>/`, restored individual tiles to
`TilesSingle/<logical-pack>/<tileset>/`, and reconstructed
WorldEd/TileZed sheets to `Tiles/<pack>/`. Each tile is first restored on its
real canvas using the atlas rectangle, offset, original name, and
`tileWidth`/`tileHeight` stored in the `.pack`. Sheets always contain eight
columns, making their pixel width exactly `8 * tileWidth`.

Files ending in `.floor.pack` are part of the matching normal pack, but their
raw atlas directories remain separate. For example,
`TilesRaw/Tiles2x.floor.pack` and `TilesRaw/Tiles2x.pack` are distinct, while
their cut floor and non-floor tiles are combined under the logical
`TilesSingle/Tiles2x.pack` directory before tilesets are rebuilt. This can
produce many images, so it is best run once per game build or tiles update.

For modded maps, keep `--tiles` pointed at the vanilla Project Zomboid `media`
folder and add `--mod-tiles` for a separate prepared asset folder. That folder
can contain `.tiles` files plus a `texturepacks/` or `texturespack/` subfolder
with the required `.pack` files. It is loaded after the vanilla media folder, so
modded sheets can be added or override matching tileset metadata without copying
anything into the game install.

RoomDef TBX files are also generated under `tmx/tbx/<cell>/`. They keep the
room mask used by WorldEd and now include a cropped `user_tiles` list plus
per-floor `<tiles layer="...">` grids for the tiles found inside the room
bounds.

Supplemental building-level TBX files are written under
`tbx_buildings/<source-cell>/`. These group the lotheader building room ids into
one file per compiled building, preserve room masks per floor, and crop the
tiles through world coordinates. They are exported for inspection/reuse and are
not yet wired back into the TMX RoomDefs.

Use `--tbx-only` when you only want RoomDef/building TBX outputs. In that mode
the converter still reads the compiled tiles and rooms, but skips `.tmx`,
`.pzw`, preview images, and `objects.lua` writing.

Tiles named `blends_natural_01_*` are filtered from TBX exports so the
building files do not carry grass/ground filler captured by the boundary margin.

## Usage

```powershell
dotnet run --project .\PZ_Mapper_Converter.csproj -- `
  --input "D:\Path\To\CompiledMap" `
  --output "D:\Path\To\Export" `
  --tiles "D:\Path\To\ProjectZomboid\media" `
  --mod-tiles "D:\Path\To\PreparedModAssets" `
  --name "MyMap" `
  --source-cell-size 256 `
  --target-cell-size 300 `
  --cells 46_26,46_27 `
  --clean
```

TBX-only inspection export:

```powershell
dotnet run --project .\PZ_Mapper_Converter.csproj -- `
  --input "D:\Path\To\CompiledMap" `
  --output "D:\Path\To\TBX_Only" `
  --source-cell-size 256 `
  --target-cell-size 300 `
  --cells 46_26 `
  --tbx-only `
  --clean
```

Tilesheet extraction can be enabled on any normal export:

```powershell
dotnet run --project .\PZ_Mapper_Converter.csproj -- `
  --input "D:\Path\To\CompiledMap" `
  --output "D:\Path\To\Export" `
  --tiles "D:\Path\To\ProjectZomboid\media" `
  --extract-tiles `
  --clean
```

`--tiles` is optional. When omitted, the converter infers tilesets from tile
names with an `8`-column fallback.

`--mod-tiles` is optional. It points to a separate mod asset root and is ignored
when omitted. The CLI also accepts `--mod-media` as an alias.

`--cells` is optional. It is useful for validating a small set of source cells
without converting an entire map folder.

`--clean` is guarded. If the output folder already contains files, the CLI asks
you to type `CLEAN` before continuing, then moves existing output contents to
the Windows Recycle Bin. It refuses protected locations such as Desktop,
Documents, Downloads, the user profile, and drive roots.

`--source-cell-size` is optional. When it is set, the converter validates the
detected `.lotheader` source cell size before exporting. Use `300` for v41 and
older maps, or `256` for Build 42 POT maps.

`--no-images` is optional. Use it when you want the map/project export without
the PNG preview images.

`--extract-tiles` is optional. It reads packs from `--tiles` and, when present,
from `--mod-tiles`. The tilesheet images are reconstructed from `.pack`
metadata and do not require a `.tiles` file. `--tiles` can point at the Project
Zomboid `media` folder, a folder containing `.pack`/`.tiles` files, or a single
`.pack` file.

`--tiles-only` performs only this pack extraction. It requires an output and at
least one tiles path, but no compiled-map input, and does not read lotheaders or
lotpacks. Studio enables this mode automatically when Tile sheets is the only
selected output.

The output TMX grid is `300x300` by default. Use `--target-cell-size 256` when
you want native Build 42-sized TMX cells instead. Internally, source tiles are
converted through world coordinates:

```text
worldX = sourceCellX * sourceCellSize + localX
targetCellX = worldX / 300
targetLocalX = worldX % 300
```
